# 批次一键执行与独立 HTML 总览设计

## 目标

将批量知识点实验收敛为“创建批次 → 执行跑批 → 查看结果”的流程。批量执行仅面向 API 自动调用模式；单 KP 实验继续保留人工确认流程。历史完成结果的 HTML 总览独立为功能入口，不嵌入批次执行页面。

## 用户流程

1. 用户在“批量实验”页导入多个 KP 并创建批次。
2. 批次创建后，运行记录区域显示“执行跑批”按钮。
3. 点击后按批次内顺序处理所有未完成 KP：阶段 1 KU 划分、覆盖校验、阶段 2 属性与内容要素抽取、保存最终结果。
4. 单个 KP 失败时记录失败原因并继续处理其他 KP。
5. 批次完成后显示成功数、失败数，并提供“查看批次结果”入口。
6. “HTML 总览”作为独立页面，加载所有 COMPLETED 记录，支持知识点切换、图谱查看和节点证据查看。

## 状态与数据流

- 批次创建：批次为 `PENDING`，子记录为 `PENDING`。
- 开始执行：批次进入执行中；子记录按阶段更新为 `STAGE1_IN_PROGRESS`、`STAGE2_IN_PROGRESS`。
- 成功：子记录保存最终 JSON 并标记 `COMPLETED`。
- 失败：子记录标记 `FAIL`，保存错误描述；执行器继续下一条。
- 所有子记录完成后，批次为 `COMPLETED`；存在失败时批次保留可区分的失败/部分失败结果，并允许重跑失败项。
- 已完成子记录跳过，避免重复调用模型。

## 页面结构

- 批量实验：创建批次、选择批次、查看进度、执行跑批、查看批次结果。
- HTML 总览：独立选择器切换所有历史完成 KP，展示图谱和完整抽取结果。
- 历史运行：保留记录列表和单条图谱查看，不再嵌入完整 HTML 总览。

## 错误处理与验证

- 每个 KP 的阶段 1 和阶段 2 均复用现有解析、覆盖校验和最终结果校验。
- 单条异常捕获后写入该运行记录的失败状态与描述。
- 批次执行完成后刷新批次统计；按钮状态根据批次是否还有未完成项决定。
- 使用现有测试/校验命令，并增加针对批次执行器和 HTML 总览入口的回归检查。

## 取舍

采用页面内同步顺序执行，改动范围小且符合当前 Streamlit 架构。后续若批次规模很大，再考虑后台队列；本次不引入新的任务系统。
