# Stage 1 提示词 v1.13 设计

## 目标

基于 v1.10 新增 Stage 1 提示词 v1.13，改善 Sol medium 对明确上层主题的过度合并，同时避免 v1.12 将连续流程和嵌套分项普遍过拆的问题。

v1.13 不改变默认提示词版本，不自动标记为推荐版本。是否推荐由后续基准测试和重复稳定性测试决定。

## 核心边界规则

编号层级只提供作者结构证据，不直接决定 KU 边界。

1. 一级主题作为候选边界检查。只有相邻一级主题分别具有独立使用目的、完整知识结果，并且不是整体与步骤、主题与组成、正常流程与异常处理等从属关系时，才建立边界。
2. 嵌套分项默认保留在所属上层主题中。分类维度、具体类别、参数、措施、连续步骤、检查项目、例外和异常处理不得仅因编号不同而独立成 KU。
3. 一级编号如果只是同一专业任务的连续阶段，应合并为一个 KU。准备、实施、检查、处置等阶段的先后顺序不能单独证明应拆分。
4. “可以单独描述、单独命题或单独概括”不等于“应独立成 KU”。独立 KU 必须具有可单独使用的知识目的和完整结果。
5. 同一对象下可以存在多个 KU，但必须有不同的直接专业任务或知识成果；共享对象不能作为强制合并依据。

## 判定顺序

模型先建立作者语义树，再按以下顺序判断：

1. 确定上层主题、嵌套分项和连续阶段。
2. 将嵌套分项默认归入最近的上层主题。
3. 对相邻上层主题执行独立性检查：使用目的是否不同、两侧是否各自完整、是否存在从属关系。
4. 对候选边界执行连续流程反证：如果两侧共同完成一个不可分割的专业任务，则撤销边界。
5. 最后执行双向复核，同时检查过度拆分和过度合并。

不得沿用 v1.12 的“分别概括出不同直接结果就倾向拆分”的强规则，因为连续流程中的阶段也可能被概括为不同局部结果。

## 与基准的预期对应

- B01、B08、B10：一级或嵌套步骤共同完成连续任务，保持 1 KU。
- B02、B03：拆分上层专业任务，保留任务内部的成孔方法、控制项目和异常处置。
- B04：钢管柱与钢管拱属于不同结构对象和独立施工任务，应拆分。
- B05：两套分类目的或分类视角形成 2 KU，各分类视角内部的维度和类别不拆。
- B06、B09：多个一级主题分别形成可独立使用的专业结果，应拆分。
- B07：性能要求、储存、施工安装形成三个任务，安装内部步骤不拆。

## 文件与兼容性

- 新增 `prompts/ku_split/v1.13.md`。
- 在现有 Stage 1 提示词测试中增加 v1.13 的关键规则断言。
- 不修改 v1.6 默认值。
- 不修改 v1.6、v1.10 的推荐标记。
- 不修改既有提示词文件和评测基准。
- 服务动态发现新提示词版本，不需要重启。

## 验证

1. 运行 Python 编译检查。
2. 运行 Stage 1 提示词单元测试。
3. 确认提示词版本列表包含 v1.13。
4. 使用 `v1.13-temp0-sol-medium-benchmark06` 执行首次基准测试。
5. 首次测试后再决定是否进行三次重复稳定性测试；单次结果不触发继续扩充提示词。
