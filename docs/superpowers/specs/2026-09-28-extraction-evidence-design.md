# 抽取拆分证据升级设计

## 目标

阶段 1 的 KU 拆分和阶段 2 的内容要素拆分都必须生成可读的拆分证据。证据用于实验审核、规则优化和结果追溯，但不属于正式知识属性，也不写入 Neo4j 知识图谱本体。

## 数据设计

最终结果在顶层增加独立的 `evidence` 区域，不向 `FinalKU` 或 `ContentElement` 增加证据属性：

```json
{
  "kp": {},
  "knowledge_units": [],
  "stage1_validation": {},
  "evidence": {
    "ku_split": [
      {"ku_id": "KP_001_KU_01", "evidence": "……"}
    ],
    "content_element_split": [
      {"ku_id": "KP_001_KU_01", "element_id": "CE_01", "evidence": "……"}
    ]
  }
}
```

阶段 1 和阶段 2 的模型结果可以携带各自的证据对象，程序在生成最终结果时统一转换为顶层 `evidence`。证据只包含自然语言说明，不输出 `source_block_ids`、页码或偏移量。旧结果缺少 `evidence` 时按空证据兼容读取。

## 提示词要求

阶段 1 要求为每个 KU 说明：该内容为何构成完整论述模块，以及它与相邻内容形成边界或应当合并的语义依据。不得仅用标题、编号、篇幅、信息密度或可命题性作为证据。

阶段 2 要求为每个内容要素说明：所含内容共同回答什么子问题，为何应合并为一个要素，以及为何无需继续机械拆分。证据必须来自当前 KU 原文，不得补充外部知识。

## 展示设计

最终结果详情页在 KU 教材原文下显示“KU 拆分证据”，并在内容要素内容下显示“内容要素拆分证据”。图谱本体仍只有 KP、KU、内容要素和正式关系；点击 KU 或内容要素节点时，前端根据 ID 查找证据并在右侧详情面板中展示。缺失证据的历史结果显示“暂无拆分证据”。

## Neo4j 边界

正式入库只写确认后的知识节点、业务属性、关系、教材原文和必要来源定位。完整拆分证据保留在实验批次结果中，不创建证据节点、不创建证据关系，也不写成知识节点属性。若未来需要跨系统追溯，只保存 `batch_id` 或 `evidence_ref`。

## 校验与兼容

- 新任务要求 KU 和内容要素证据非空。
- 验证器校验证据引用的 KU、内容要素确实存在，且引用唯一。
- 不要求也不接受 `source_block_ids` 作为证据输出。
- 旧结果可以继续加载、查看和导出。
- 图谱构建测试验证证据只进入查看数据，不成为知识属性、节点或关系。

## 验收标准

1. 新阶段 1、阶段 2 任务的提示词和 JSON 输出均包含自然语言证据。
2. 最终结果顶层存在独立 `evidence`，知识实体模型中没有证据字段。
3. 页面和完整报告点击节点时能在教材原文或内容下方查看证据。
4. 历史结果不报错，并显示无证据提示。
5. Neo4j 导出路径不包含完整证据文本。
6. 自动化测试覆盖模型解析、引用校验、最终合并、图谱展示和向后兼容。
