# 开放式知识类型与内容要素类型设计

## 目标

升级两个阶段的默认提示词，使系统不再用 `OTHER` 吞掉无法匹配固定枚举的知识，而是根据教材语义生成可供 Agent 使用的类型标识和中文类型名称。

## 边界

- Stage 1 V1.4 仍只负责连续 KU 划分、标题和统领性主问题，不负责知识类型判断。
- Stage 2 V1.3 负责在已确认的 KU 内生成 `knowledge_type`、`knowledge_type_name`、`element_type` 和 `element_type_name`。
- 类型标识为开放字符串；模型应优先复用语义相同的类型，确无合适类型时创建新的稳定英文标识。
- `OTHER` 不得作为新结果的类型值。历史结果仍允许被读取，以保证兼容性。

## 数据结构

`knowledge_type` 与 `element_type` 从固定 Literal 改为字符串。新增 `knowledge_type_name`，并保留内容要素已有的 `element_type_name`。中文名称必须清晰表达知识角色，不得只是教材中的具体对象名称。

## 验证与展示

提示词示例、报告和测试同步使用开放类型。系统不再依赖固定枚举映射；旧结果中的 `OTHER` 可以展示和读取，但新阶段2提示词明确禁止生成。

## 验收标准

1. 两个新提示词可被加载，Stage 1 默认使用 V1.4，Stage 2 默认使用最新版本 V1.3。
2. 新模型可解析自定义类型，例如 `STRUCTURAL_COMPONENT` / `结构组成部分`。
3. 新提示词中不存在要求输出 `OTHER` 的规则或示例。
4. 旧结果仍能加载，现有阶段1、阶段2、报告和持久化测试不回归。
