# Prompt 使用记录设计

## 目标

每次实验运行都记录实际提交的提示词来源和内容，使历史运行可以还原当时使用的提示词，即使提示词文件之后被修改。

## 数据设计

在 `experiment_run` 中增加：

- `prompt_kind`：`ku_split` 或 `ku_extract`。
- `prompt_content`：运行时实际提交给 Codex/API 的完整提示词文本。

现有 `prompt_version` 保留，用于记录用户选择的版本号。旧数据库通过启动时迁移自动补充新列，已有记录保持为空，不伪造历史内容。

## 运行链路

Stage 1 和 Stage 2 的四种保存路径（Codex 待办、API 运行、加载 Codex Stage 1 结果、加载 Codex Stage 2 结果）统一传入提示词类型、版本和运行时提示词内容。加载结果时沿用创建任务时保存的会话信息，避免因用户后来切换提示词而记录错误版本。

## 历史界面

历史表显示提示词类型和版本。选择一条运行后，展开显示该次实际使用的完整提示词；旧记录没有内容时显示“历史记录未保存提示词内容”。

## 验证

- RunStore 新字段可写入并读取。
- 旧数据库启动后可正常迁移。
- 四种运行保存路径传递正确的类型、版本和内容。
- Streamlit AppTest 启动和历史展示不报错。
