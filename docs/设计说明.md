# 教材知识单元 AI 抽取实验台｜设计说明 V1.0

## 目标

V1.0 只验证两条链路：

1. KP → KU 完整语义分区；
2. 已确认 KU → 属性与内容要素结构化抽取。

关系抽取、考点、真题、Neo4j、Milvus 均不进入 V1.0。

## 模式 A：Codex Workspace

- Streamlit 负责输入、Source Block、Coverage、人工确认、展示与导出。
- 点击模型步骤时，程序生成 `.kg_tasks/pending/<run>_<stage>/task.md + input.json`。
- 当前 Codex 会话读取任务，按 `AGENTS.md` 与 Skill 执行语义工作并写回 `result.json`。
- Streamlit 再加载并做确定性校验。
- 优点：早期无需 API Key，团队成员只要在各自 Codex 中打开仓库即可使用同一工作流。
- 限制：按钮不能无感直接调用“当前 Codex 账号额度”，中间需要一次 Codex 会话指令“处理最新任务”。

## 模式 B：API 自动调用

- UI、Schema、Coverage、Prompt 完全复用模式 A。
- 模型调用由 `OpenAICompatibleClient` 完成。
- 可配置 Base URL、API Key、Model、Temperature。
- 适合 Prompt 稳定后的批量与自动化实验。

## 为什么使用 Source Block

不要求模型输出字符 offset，也不信任模型重新复制原文。程序先把 KP 原文做无损技术分块：

`S0001, S0002, ...`

模型只选择每个 KU 的 `start_block_id/end_block_id`。最终 KU `source_text` 由程序根据原始 KP 精确截取，因此能确定性验证：

- 100% Coverage；
- Gap = 0；
- Overlap = 0；
- Order 正确；
- KU 原文拼接 == KP 原文。

Source Block 不是知识实体，只是“地址”。

## 数据闸门

Stage 1 必须 Coverage PASS，并由用户点击“确认 KU 划分”后，Stage 2 才可执行。这是实验期的关键控制点，用于防止错误 KU 边界污染属性抽取结果。
